# Сценарий демо (≈2 минуты)

Четыре шага: (a) чистый кейс FU19, (b) ошибка TO42, (c) неполный TO37 с блоком «Допишите», (d) пакетная проверка CSV. Кейсы из набора QA (`qa/cases.csv`), проверены на текущей версии `main` с индексом `catalog.db` (запрос `POST /api/analyze` с `domain_hint`). Скорость: медиана ~50 мс, в демо 100–200 мс, первый запрос до 0,5 с.

**Перед показом:** запустить `uvicorn app.main:app --port 8000`, открыть http://localhost:8000, вкладка «Создание СТЕ». Кнопка запуска называется **«Проверить»**. Держать под рукой `docs/demo_batch.csv` и папку `docs/screens/` (план Б).

Важно для ведущего: воронка заканчивается не одним кодом, а группой из 2–3 вариаций одного наименования. Это нормально: код КТРУ определяется до наименования, а различия между вариациями задают обязательные характеристики, которые мы и просим заполнить. Пустые строки в таблице без пометки «обязательная» — необязательные: их можно оставить пустыми, на статус карточки они не влияют.

## (a) Чистый ввод — FU19, кресло офисное (≈30 с)

**Ввод (категория «Мебель»), нажать «Проверить»:**
```
Кресло офисное обивка ткань цвет черный высота 1080 мм ширина 650 мм глубина 450 мм
```

**Что видит зал:**
- Статус `ok`, лучший код **31.01.12.160-00000005 «Кресло офисное»**.
- Воронка: **355 → 2 → 2 → 2** (Домен → Наименование → ОКПД2 → Итог), у каждого шага причина.
- Таблица: Высота 1080 мм, Ширина 650 мм, Глубина 450 мм, Цвет черный — бейдж **Портал**.
- Две строки с бейджем **КТРУ**: «Вид материала обивки спинки» и «Вид материала обивки сиденья» — обязательные для кода; из слов «обивка ткань» ядро уже подставило в обе значение «Текстиль».
- Бейджи: **Код: определён**, **Карточка: заполнена**, строка «2/2 обязательных, 4/5 необязательных». Одна пустая строка — «Вид материала крестовины», без пометки «обязательная»: её можно не заполнять.

**Говорим:** «Обычное описание — код найден, характеристики привязаны к источникам, обязательные уже заполнены. Карточка готова». Дальше не правим — экономим время.

## (b) Ввод с ошибкой — TO42, нереалистичная длина (≈30 с)

**Ввод (категория «Инструменты»), нажать «Проверить»:**
```
Ключ гаечный 170х190 мм длина 27 м
```

**Что видит зал:**
- Статус `error`, код **25.73.30.171-00000001 «Ключ гаечный разводной»** (верная группа найдена несмотря на ошибку).
- В превью под полем описания фрагмент **«27 м»** подсвечен красным, при наведении — текст ошибки.
- Ошибка: ««длина» = 27 м нереалистично для ручного инструмента (больше 3 м)», ожидается «до 3 м», варианты «27 мм», «27 см». В таблице значение пересчитано в единицу КТРУ: 27000 мм.
- Блок «Было → стало»: «27 м → 27000 мм».
- Воронка: **1514 → 3 → 3 → 3 → 3** (шаг «длина»: коды не отсеяны — ошибочное значение не фильтрует, а подсвечивается).
- Бейджи: **Код: определён**, **Карточка: есть ошибки**, «0/1 обязательных, 1/2 необязательных»; плюс незаполненная обязательная «Тип исполнения» (допустимо «B»).

**Что делаем (исправление):** в поле описания меняем «27 м» на «270 мм» (правку делаем именно в тексте — так надёжнее для демо) и снова «Проверить».

**Результат:** ошибка исчезает, красная подсветка пропадает; остаётся только незаполненный «Тип исполнения» — его покажем на следующем кейсе.

## (c) Неполный ввод — TO37, «Ключ» + блок «Допишите» (≈25 с)

**Ввод (категория «Инструменты»), нажать «Проверить»:**
```
Ключ
```

**Что видит зал:**
- Статус `need_more`, лучший код **25.73.30.171-00000001 «Ключ гаечный разводной»**.
- Воронка: **1514 → 3 → 3 → 3**.
- Подсказка «Не удалось выделить характеристики из текста» с примером формата.
- Бейджи: **Код: определён**, **Карточка: не хватает обязательных: 1**, «0/1 обязательных, 0/2 необязательных».
- Блок **«Допишите ещё …»**: обязательная «Тип исполнения» (бейдж **КТРУ**) с чипом допустимого значения **«B»**; ниже — необязательные.

**Что делаем:** один клик по чипу **«B»** в блоке «Допишите».

**Результат:** статус `ok`, бейдж **Карточка: заполнена** («1/1 обязательных, 0/3 необязательных»), воронка **1514 → 3 → 3 → 2 → 2**, характеристика сузила коды, замечаний нет.

## (d) Пакетная проверка CSV (≈35 с)

**Что делаем:** вкладка **«Пакетная проверка (CSV)»** → перетащить или выбрать `docs/demo_batch.csv` (11 наименований: те же кейсы плюс стеллаж, футболка, куртка, костюм, дрель, мусорная строка «x»).

**Что видит зал (сводка над таблицей):**
- Обработано 11 из 11, общее время ≈1 с.
- Код: **определён 8**, **несколько вариантов 2**, **не найден 1**.
- Карточка: **заполнена 4**, **неполная 6**, **с ошибками 1** (строка «Ключ гаечный 170х190 мм длина 27 м» — с замечанием про 27 м).

**Что делаем:** щёлкаем по строке (например, «Ключ гаечный 170х190 мм длина 27 м») — она открывается в редакторе; возвращаемся и жмём **«Выгрузить результат (CSV)»**.

## Текст для ведущего (~2 минуты)

> Поставщик пишет описание товара как привык — одной строкой. Покажу четыре случая.
>
> Первый — нормальное описание кресла. Нажимаю «Проверить» — сервис за доли секунды разобрал строку: высота, ширина, глубина, цвет с бейджем «Портал». Из 355 кодов мебели по названию осталось два — оба «Кресло офисное». Обязательные материалы обивки уже подставлены из слов «обивка ткань» — карточка заполнена.
>
> Второй — ошибка: длина ключа 27 метров. Группу кода мы нашли верно, но «27 м» подсвечено красным: для ручного инструмента это нереалистично, предлагаем 27 миллиметров или сантиметров, а блок «было → стало» показывает, что мы сделали со значением. Исправляю на 270 миллиметров — ошибка ушла.
>
> Третий — поставщик написал одно слово «Ключ». Мы не угадываем: статус «нужно уточнение» и блок «Допишите» с допустимым значением из КТРУ. Один клик по чипу — воронка сужается с трёх кодов до двух, статус «ок».
>
> И пакетный режим: загружаю CSV из 11 строк — примерно за секунду: 8 кодов определены, 2 неоднозначны, 1 не найден; 4 карточки заполнены, 6 неполные, 1 с ошибкой. Щелчок по строке открывает её в редакторе, результат выгружается в CSV.
>
> Итог: каждое решение объяснено — источник характеристики, причина сужения, подсказка. Всё работает без нейросетей и без интернета, медиана ответа около 50 миллисекунд.
