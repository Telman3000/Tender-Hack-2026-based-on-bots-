# Сценарий демо (≈2 минуты)

Три кейса из набора QA (`qa/cases.csv`): чистый, неполный и с ошибкой. Все три проверены на текущей версии `main` с индексом `catalog.db` (запрос `POST /api/analyze` с `domain_hint`), время ответа 45–60 мс. Перед показом: запустить `uvicorn app.main:app --port 8000`, открыть http://localhost:8000.

Важно для ведущего: воронка заканчивается не одним кодом, а группой из 2–3 вариаций одного наименования. Это нормально: код КТРУ определяется до наименования, а различия между вариациями задают обязательные характеристики, которые мы и просим заполнить.

---

## Кейс 1. Чистый ввод — FU19, кресло офисное

**Ввод (домен «мебель»):**
```
Кресло офисное обивка ткань цвет черный высота 1080 мм ширина 650 мм глубина 450 мм
```

**Что видит зал:**
- Статус `ok`, лучший код **31.01.12.160-00000005 «Кресло офисное»**.
- Воронка: **355 → 2 → 2 → 2** (Домен → Наименование → ОКПД2 → Итог), у каждого шага причина.
- Таблица: Высота 1080 мм, Ширина 650 мм, Глубина 450 мм, Цвет черный — бейдж **Портал**.
- Две пустые строки с бейджем **КТРУ**: «Вид материала обивки спинки» и «Вид материала обивки сиденья» — обязательные для кода, но не заполнены.

**Что делаем:** в таблице заполняем «Вид материала обивки спинки» = «Ткань сетчатая армированная», «Вид материала обивки сиденья» = «Экокожа» (варианты из списка КТРУ).

**Результат после пересчёта:** замечаний нет, в воронке появляются шаги по двум новым характеристикам (355 → 2 → 2 → 2 → 2 → 2), код тот же.

## Кейс 2. Неполный ввод — TO37, «Ключ»

**Ввод (домен «инструменты»):**
```
Ключ
```

**Что видит зал:**
- Статус `need_more`, лучший код **25.73.30.171-00000001 «Ключ гаечный разводной»**.
- Воронка: **1514 → 3 → 3 → 3**.
- Подсказки: «Не удалось выделить характеристики из текста» с примером формата и обязательная характеристика КТРУ «Тип исполнения» (пустая строка с бейджем **КТРУ**, допустимое значение «B»).

**Что делаем:** заполняем «Тип исполнения» = «B».

**Результат:** статус `ok`, воронка **1514 → 3 → 3 → 2 → 2**, характеристика сузила коды, замечаний нет.

## Кейс 3. Ввод с ошибкой — TO42, нереалистичная длина

**Ввод (домен «инструменты»):**
```
Ключ гаечный 170х190 мм длина 27 м
```

**Что видит зал:**
- Статус `error`, код **25.73.30.171-00000001 «Ключ гаечный разводной»** (верная группа найдена несмотря на ошибку).
- Воронка: **1514 → 3 → 3 → 3 → 3** (шаг «длина»: коды не отсеяны — ошибочное значение не фильтрует, а подсвечивается).
- Ошибка: «Длина разводного ключа = 27 м нереалистично для ручного инструмента (больше 3 м)», варианты «27 мм», «27 см». В таблице значение пересчитано в единицу КТРУ: 27000 мм.
- Плюс обязательная «Тип исполнения» не заполнена.

**Что делаем:** в поле описания исправляем «27 м» на «270 мм» (правку делаем именно в тексте — так надёжнее для демо), затем заполняем «Тип исполнения» = «B».

**Результат:** после исправления длины ошибка исчезает (остаётся только незаполненный «Тип исполнения»), после заполнения — статус `ok`.

## Текст для ведущего (~2 минуты)

> Поставщик пишет описание товара как привык — одной строкой. Покажу три случая.
>
> Первый — нормальное описание кресла. Сервис за 50 миллисекунд разобрал строку: высота, ширина, глубина, цвет. Бейдж «Портал» значит, что такие характеристики есть в карточках портала. Справа воронка: из 355 кодов мебели по названию осталось два — оба «Кресло офисное». Но система видит, что у этого кода КТРУ есть две обязательные характеристики — материал обивки спинки и сиденья. Они уже стоят в таблице с бейджем «КТРУ». Заполняю из допустимых значений — замечаний нет, карточка готова.
>
> Второй случай — поставщик написал одно слово «Ключ». Мы не угадываем: статус «нужно уточнение», показываем три подходящих кода и говорим, чего не хватает — обязательный «Тип исполнения». Заполняю — воронка сужается с трёх кодов до двух, статус «ок».
>
> Третий — ошибка: длина ключа 27 метров. Группу кода мы всё равно нашли верно, но выдаём ошибку: для ручного инструмента это нереалистично, и предлагаем варианты — 27 миллиметров или сантиметров. Обратите внимание: ошибочное значение не выкидывает коды из воронки, а подсвечивается. Исправляю на 270 миллиметров — ошибка ушла.
>
> Итог: каждая характеристика привязана к источнику — КТРУ, портал или новая, каждое сужение объяснено, а ошибки ловятся до отправки карточки. По прогону QA на 45 кейсах: верный код в топ-3 в 80% случаев, ложно-уверенных ответов на ошибочном вводе — ноль, ответ около 50 миллисекунд. Цифры на текущей версии, будут обновлены.
