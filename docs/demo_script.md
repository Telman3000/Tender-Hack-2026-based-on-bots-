# Сценарий демо (≈2 минуты)

Шесть шагов: (a) чистый кейс FU19, (b) ошибка TO42, (c) неполный TO37 с блоком «Допишите», (c2) бессмысленная характеристика, (c3) товар не нашей категории, (d) пакетная проверка CSV. Кейсы из набора QA (`qa/cases.csv`). **Сценарий рассчитан на `main` ab39ee1** (ядро с пакетным API, `out_of_scope`, `suspicious`, `fill`; индекс — 3030 позиций КТРУ), все строки «Что видит зал» сверены вживую в UI на `main` ab39ee1 с индексом `catalog.db` (запрос `POST /api/analyze` с `domain_hint`). Скорость: медиана ~50 мс, в демо 100–200 мс, первый запрос до 0,5 с.

**Перед показом:** запустить `uvicorn app.main:app --port 8000`, открыть http://localhost:8000, вкладка «Создание СТЕ». Кнопка запуска называется **«Проверить»**. Держать под рукой `docs/demo_batch.csv` и папку `docs/screens/` (план Б).

Важно для ведущего: воронка часто заканчивается не одним кодом, а группой из 2–3 вариаций одного наименования (у ключей — 3, у FU19 — сразу 1). Это нормально: код КТРУ определяется до наименования, а различия между вариациями задают обязательные характеристики, которые мы и просим заполнить. Пустые строки в таблице без пометки «обязательная» — необязательные: их можно оставить пустыми, на статус карточки они не влияют.

## (a) Чистый ввод — FU19, кресло офисное (≈30 с)

**Ввод (категория «Мебель»), нажать «Проверить»:**
```
Кресло офисное обивка ткань цвет черный высота 1080 мм ширина 650 мм глубина 450 мм
```

**Что видит зал:**
- Статус «Код КТРУ определён» (`ok`), лучший код **31.01.12.160-00000006 «Кресло офисное»**.
- Воронка: **313 → 1 → 1 → 1** (Домен → Наименование → ОКПД2 → Итог), у каждого шага причина.
- Таблица: Высота 1080 мм, Ширина 650 мм, Глубина 450 мм, Цвет черный — бейдж **Портал**.
- Две строки с бейджем **КТРУ**: «Вид материала обивки спинки» и «Вид материала обивки сиденья» — обязательные для кода; из слов «обивка ткань» ядро уже подставило в обе значение «Текстиль».
- Бейджи: **Код: определён**, **Карточка: заполнена**, строка «2/2 обязательных, 4/8 необязательных».
- Блок **«Допишите ещё 4 характеристики»**, счётчик «Заполнено 2 из 6 характеристик КТРУ (обязательных 2 из 2)»: Назначение, Вид материала крестовины, Вид материала подлокотника, Конструктивные особенности — все необязательные (серые), их можно не заполнять.

**Говорим:** «Обычное описание — код найден, характеристики привязаны к источникам, обязательные уже заполнены. Карточка готова». Дальше не правим — экономим время.

## (b) Ввод с ошибкой — TO42, нереалистичная длина (≈30 с)

**Ввод (категория «Инструменты»), нажать «Проверить»:**
```
Ключ гаечный 170х190 мм длина 27 м
```

**Что видит зал:**
- Статус «Есть ошибки в характеристиках» (`error`), код **25.73.30.171-00000001 «Ключ гаечный разводной»** (верная группа найдена несмотря на ошибку).
- В превью под полем описания фрагмент **«27 м»** подсвечен красным, при наведении — текст ошибки.
- Ошибка: ««длина» = 27 м нереалистично для ручного инструмента (больше 3 м)», ожидается «до 3 м», варианты «27 мм», «27 см». В таблице значение пересчитано в единицу КТРУ: 27000 мм.
- Блок «Было → стало»: метка «единицы», «Длина разводного ключа: 27 м → 27000 мм».
- Воронка: **1309 → 3 → 3 → 3 → 3** (шаг «длина»: коды не отсеяны — ошибочное значение не фильтрует, а подсвечивается).
- Бейджи: **Код: определён**, **Карточка: есть ошибки**, «0/1 обязательных, 1/3 необязательных»; плюс незаполненная обязательная «Тип исполнения» (допустимо «B»).
- Блок «Допишите ещё 3 характеристики (обязательных: 1)», счётчик «Заполнено 1 из 4 характеристик КТРУ (обязательных 0 из 1)».

**Что делаем (исправление):** в поле описания меняем «27 м» на «270 мм» (правку делаем именно в тексте — так надёжнее для демо) и снова «Проверить».

**Результат:** статус «Нужны уточнения», бейдж **Карточка: не хватает обязательных: 1**; ошибка и блок «Было → стало» исчезают, красная подсветка пропадает, в таблице «Длина разводного ключа = 270 мм», воронка та же **1309 → 3 → 3 → 3 → 3**; остаётся только незаполненный «Тип исполнения» — его покажем на следующем кейсе.

## (c) Неполный ввод — TO37, «Ключ» + блок «Допишите» (≈25 с)

**Ввод (категория «Инструменты»), нажать «Проверить»:**
```
Ключ
```

**Что видит зал:**
- Статус «Нужны уточнения» (`need_more`), лучший код **25.73.30.171-00000001 «Ключ гаечный разводной»**.
- Воронка: **1309 → 3 → 3 → 3**.
- Подсказка «Не удалось выделить характеристики из текста» с примером формата.
- Бейджи: **Код: определён**, **Карточка: не хватает обязательных: 1**, «0/1 обязательных, 0/3 необязательных».
- Блок **«Допишите ещё 4 характеристики (обязательных: 1)»**, счётчик «Заполнено 0 из 4 характеристик КТРУ (обязательных 0 из 1)»: сверху обязательная «Тип исполнения» (бейдж **КТРУ**) с чипом допустимого значения **«B»**; ниже серым — необязательные.

**Что делаем:** один клик по чипу **«B»** в блоке «Допишите».

**Результат:** статус «Код КТРУ определён» (`ok`), бейдж **Карточка: заполнена** («1/1 обязательных, 0/3 необязательных»), счётчик «Заполнено 1 из 4 характеристик КТРУ (обязательных 1 из 1)», воронка **1309 → 3 → 3 → 2 → 2**, характеристика сузила коды, замечаний нет.

## (c2) Бессмысленная характеристика — «мощность» у ключа (≈15 с)

**Ввод (категория «Инструменты»), нажать «Проверить»:**
```
Ключ гаечный 17х19 мм мощность 100 Вт
```

**Что видит зал:**
- Статус «Нужны уточнения», код **25.73.30.171-00000001 «Ключ гаечный разводной»**, воронка **1309 → 3 → 3 → 3**.
- Бейджи: **Код: определён**, **Карточка: не хватает обязательных: 1**, «0/1 обязательных, 1/4 необязательных»; блок «Допишите ещё 4 характеристики (обязательных: 1)», счётчик «Заполнено 0 из 4 характеристик КТРУ (обязательных 0 из 1)».
- В превью под полем фрагмент **«100 Вт»** подсвечен (предупреждение).
- Замечание: «Мощность: Характеристика не подходит к типу товара: «Мощность 100 Вт» не встречается у позиций КТРУ «Ключ гаечный разводной» — проверьте ввод», ожидается «характеристика, применимая к «Ключ гаечный разводной»».
- В таблице строка «Мощность = 100 Вт» стоит **последней**, с оранжевой меткой **«подозрительно»**; в коды КТРУ она не попадает и воронку не сужает.

**Говорим:** «Мы не выкидываем то, что написал поставщик, но и не верим вслепую: мощности у гаечного ключа не бывает — помечаем и просим проверить».

## (c3) Не наша категория — бумага (≈10 с)

**Ввод (категория не выбрана), нажать «Проверить»:**
```
Бумага А4 500 листов
```

**Что видит зал:**
- Статус **«Не наша категория»**, бейджи **Код: не найден**, **Карточка: неполная**.
- Блок с меткой **«Не наша категория»** и текстом «товар не относится к поддерживаемым категориям (мебель, одежда, инструменты) или не распознан. Код КТРУ не подбирается.»
- Таблица пуста («Характеристики не найдены»), кода нет, воронка **3030 → 0**; в замечаниях — «Не удалось выделить характеристики из текста» с примером формата.

**Говорим:** «Мы честно говорим "не наше", а не подбираем случайный код». Мусорная строка «x» даёт тот же результат.

## (d) Пакетная проверка CSV (≈35 с)

**Что делаем:** вкладка **«Пакетная проверка (CSV)»** → перетащить или выбрать `docs/demo_batch.csv` (13 наименований: те же кейсы плюс стеллаж, футболка, куртка, костюм, дрель, мусорная строка «x», «Ключ гаечный 17х19 мм мощность 100 Вт» и «Бумага А4 500 листов»). Строки появляются по мере обработки (потоковый режим `/api/analyze/batch?stream=1`, подпись «Режим: потоковый API» под кнопкой).

**Что видит зал (сводка над таблицей):**
- Обработано 13 из 13, общее время ≈0,5 с (при повторном запуске; первый запуск после старта сервера — до ~1,3 с).
- Код: **определён 9**, **несколько вариантов 2**, **не найден 0**, **не наша категория 2** («x» и бумага).
- Карточка: **заполнена 4**, **неполная 8**, **с ошибками 1** (строка «Ключ гаечный 170х190 мм длина 27 м» — с замечанием про 27 м).

**Что делаем:** щёлкаем по строке (например, «Ключ гаечный 170х190 мм длина 27 м») — она открывается в редакторе; возвращаемся и жмём **«Выгрузить результат (CSV)»**.

## Текст для ведущего (~2 минуты)

> Поставщик пишет описание товара как привык — одной строкой. Покажу четыре случая.
>
> Первый — нормальное описание кресла. Нажимаю «Проверить» — сервис за доли секунды разобрал строку: высота, ширина, глубина, цвет с бейджем «Портал». Из 313 кодов мебели по названию остался один — «Кресло офисное». Обязательные материалы обивки уже подставлены из слов «обивка ткань» — карточка заполнена.
>
> Второй — ошибка: длина ключа 27 метров. Группу кода мы нашли верно, но «27 м» подсвечено красным: для ручного инструмента это нереалистично, предлагаем 27 миллиметров или сантиметров, а блок «было → стало» показывает, что мы сделали со значением. Исправляю на 270 миллиметров — ошибка ушла.
>
> Третий — поставщик написал одно слово «Ключ». Мы не угадываем: статус «нужно уточнение» и блок «Допишите» с допустимым значением из КТРУ. Один клик по чипу — воронка сужается с трёх кодов до двух, статус «ок».
>
> Если поставщик приписал ключу «мощность 100 Вт» — строка помечена «подозрительно» и уходит в конец таблицы. А «бумагу А4» мы честно называем не нашей категорией и код не подбираем.
>
> И пакетный режим: загружаю CSV из 13 строк — меньше чем за секунду, строки появляются по ходу: 9 кодов определены, 2 неоднозначны, 2 строки — не наша категория; 4 карточки заполнены, 8 неполные, 1 с ошибкой. Щелчок по строке открывает её в редакторе, результат выгружается в CSV.
>
> Итог: каждое решение объяснено — источник характеристики, причина сужения, подсказка. Всё работает без нейросетей и без интернета, медиана ответа около 50 миллисекунд.
